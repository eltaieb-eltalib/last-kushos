# 01 — البنية (Architecture)

## الفكرة
النظام الضيف (Kush) **لا يحتوي أي ذكاء اصطناعي**. كل التحكم يأتي من **خارج** الآلة الافتراضية:

```
 المستخدم (CLI / REST / لاحقاً واتساب ومكالمات)
        │  مهمة + prompt
        ▼
 ┌──────────────┐   يختار النموذج    ┌──────────────────────────────┐
 │ Model Router │ ─────────────────▶ │ Model Adapters                │
 │ (@alias/YAML)│                    │  Claude (computer toolset)    │
 └──────────────┘                    │  OpenAI-compatible (GPT/محلي) │
                                     └──────────────┬───────────────┘
                                                    │ Action(name, input)
                                                    ▼
 ┌──────────────┐  allow/ask/deny   ┌──────────────────────────────┐
 │   Policy     │ ◀──────────────── │ Agent loop (agent/loop.py)    │──▶ runs/<time>/steps.jsonl + shot-*.png
 └──────────────┘                   └──────────────┬───────────────┘
                                                   │
                                                   ▼
                                    ┌──────────────────────────────┐
                                    │ Computer (tools/computer.py) │
                                    └───────┬───────────────┬──────┘
                                  QMP (JSON)│               │ JSON-lines (serial)
                                            ▼               ▼
                              ┌──────────────────────────────────────────┐
                              │ QEMU  ── Kush OS ── kushagent.exe         │
                              │  usb-tablet, VGA, e1000, IDE, COM2        │
                              └──────────────────────────────────────────┘
```

## المكونات

| المكوّن | الملف | المسؤولية |
|---|---|---|
| اكتشاف التسريع | `vm/accel.py` | يختار kvm → whpx → hvf → tcg ويشرح السبب |
| مشغّل الآلة | `vm/qemu.py` | يبني أمر QEMU، ينشئ الأقراص (ومنها overlay على صورة ذهبية)، يشغّل ويوقف، يحفظ الحالة في `~/.kush-agent/vms/<name>/` |
| عميل QMP | `vm/qmp.py` | بروتوكول QEMU: `screendump`، `input-send-event`، `savevm/loadvm` |
| المفاتيح | `vm/keys.py` | أسماء المفاتيح (`ctrl+s`) والنص → qcodes لـ QEMU |
| الشاشة | `vm/screen.py` | تصغير الصورة لحدود النموذج وتحويل الإحداثيات (صورة ↔ شاشة ↔ 0..32767) |
| عميل النظام الضيف | `vm/guest.py` | يكلّم `kushagent.exe` (أوامر، كتابة عربي، نوافذ، ملفات) |
| الأدوات | `tools/computer.py` | الأفعال الـ 17 الموحّدة لكل النماذج |
| المحوّلات | `models/*.py` | تحويل محادثة كل مزوّد إلى `Step(actions, text, done)` |
| الموجّه | `models/router.py` | اختيار النموذج وسلسلة البدائل |
| القواعد | `agent/policy.py` | allow / ask / deny لكل فعل |
| حلقة الوكيل | `agent/loop.py` | تنفيذ، تسجيل، حدود الخطوات والوقت، تبديل النموذج عند الفشل |
| واجهة REST | `server.py` | تحكم خارجي مباشر بتوكن |
| CLI | `cli.py` | كل ما سبق من الطرفية |

## تدفق خطوة واحدة
1. المحوّل يرسل للنموذج المحادثة (المهمة + نتائج الأفعال السابقة + الصور).
2. النموذج يرد بنص و/أو أفعال (قد تكون عدة أفعال في دفعة واحدة).
3. كل فعل يمر على **Policy**: مسموح، أو يحتاج موافقة، أو ممنوع.
4. `Computer` ينفّذ الفعل عبر QMP (أو عبر kushagent للنص العربي).
5. أول فعل يفشل يوقف بقية الدفعة، وتُرد البقية بـ "Not executed".
6. النتائج (صورة أو `OK` أو خطأ) ترجع للنموذج، وتُسجَّل في `steps.jsonl`.
7. تتكرر الحلقة حتى يرد النموذج بدون أفعال (انتهت المهمة) أو يُبلغ حد الخطوات/الوقت.
